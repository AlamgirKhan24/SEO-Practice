# Checklist: Audit Quality and Delivery

Use this checklist before sharing an audit so readers can understand what was reviewed, why each issue matters, and how to act on it.

## Scope and evidence

- [ ] State the audit date, site scope, page types, and stakeholder priorities
- [ ] Document data sources, tools, collection dates, and access limitations
- [ ] Use representative URLs and explain the sampling method for large sites
- [ ] Keep observed facts, sampled results, hypotheses, and recommendations distinct
- [ ] Support each issue with reproducible evidence (URL, status, screenshot, export row, or tool output)
- [ ] Re-check high-impact findings and note any uncertainty or conflicting signals
- [ ] Avoid exposing credentials, personal data, or confidential information in deliverables

## Recommendations and priorities

- [ ] Explain the user or search impact without claiming an unmeasured ranking or traffic loss
- [ ] Identify the affected pages or templates and estimate the scope where evidence supports it
- [ ] Recommend a specific action and name dependencies or risks
- [ ] Assign severity, effort, priority, owner, and target date where known
- [ ] Separate confirmed defects from optional opportunities
- [ ] Record a baseline when a measurable outcome will be tracked

## Report and handoff

- [ ] Confirm report figures match the findings and issue tracker
- [ ] Include coverage gaps and pages or categories not reviewed
- [ ] Give every recommendation a verification method and expected evidence
- [ ] Check report links, page layout, readability, contrast, and small-screen presentation
- [ ] Remove template placeholders and internal notes
- [ ] Confirm the report and supporting files open without private or machine-specific paths
- [ ] Log the handoff and later fixes in the audit change log
